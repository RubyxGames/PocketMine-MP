# 1.0.0
Выпуск 10 ноября 2026 г.

Минорный релиз с функциональными улучшениями, **мультиверсионной** совместимостью Bedrock и оптимизацией производительности: поддержка протоколов от 1.20 до 1.26.60 (включая 1.26.10 и 1.26.60), локальный кэш ключей аутентификации Mojang/Xbox, сетевые fail-safe с таймаутом 4 с, доработки мульти-транспорта и кодирование чанков/пакетов **по версии протокола** каждого игрока.

**Совместимость плагинов:** плагины для предыдущих 5.x, как правило, работают без изменений, если они не используют внутренние API, reflection или пространства имён вроде `pocketmine\network\mcpe` и `pocketmine\data`.
Минимальную версию API в `plugin.yml` повышайте только если вам нужны новые возможности этого релиза.

**ВНИМАНИЕ:** прямое использование `pocketmine\network\mcpe` не защищено гарантиями стабильности публичного API.
При работе с пакетами укажите ограничение `mcpe-protocol` в `plugin.yml`.

## Общее

### Мультиверсионность Bedrock на одном сервере

**Зачем.** Игроки обновляют клиент не синхронно: на сети одновременно 1.20.x, 1.21.x и 1.26.60. Без мультипротокольного ядра старые клиенты отклоняются на handshake, а сервер мини-игр не может держать лобби и арены на одном процессе.

**Как устроено (цепочка).**

1. Клиент присылает `protocol` в Login/SessionStart.
2. `SessionStartPacketHandler::isCompatibleProtocol($protocol)` сверяет id со списком `ProtocolInfo::ACCEPTED_PROTOCOL`.
3. На сессии фиксируется `protocolId`; `TypeConverter::getInstance($protocolId)` выбирает переводчики блоков/предметов/NBT.
4. Исходящие `DataPacket` кодируются через `encode($out, $protocolId)`; входящие — `decode($in, $protocolId)`.
5. `ChunkCache::request(..., $typeConverter)` кэширует сжатые чанки **отдельно** на каждый protocol id.
6. `StandardPacketBroadcaster` группирует зрителей по protocol id и кодирует пакет заново для каждой группы.

**Поддерживаемые протоколы (выдержка).**

| Версия клиента (ориентир) | protocol id | Примечание |
|---|---:|---|
| 1.20.x | … | нижняя граница релиза |
| 1.21.60 | `776` | частый legacy на сетях |
| 1.26.10 | `944` | DDUI base tier |
| 1.26.60 | `2225` | целевой smoke NetherNet + DDUI |

Полный список — в исходнике `ProtocolInfo::ACCEPTED_PROTOCOL` (не дублируется в changelog: меняется с патчами bedrock-data).

**Практика для плагинов.**

- Публичный API (`Player`, `World`, события) — безопасная зона; ядро само перекодирует мир под клиента.
- Прямая работа с `pocketmine\network\mcpe` — ответственность плагина: укажите в `plugin.yml` директиву `mcpe-protocol` и тестируйте на минимальной и максимальной версии из таблицы.
- Не кэшируйте один закодированный `LevelChunkPacket` «для всех» — у игроков разный wire.

**Ограничения.**

- Мультипротокольность покрывает **wire и палитры**, не заменяет кастомный контент: block/item, которых нет в bedrock-data конкретной версии, по-прежнему могут отображаться как unknown.

## Производительность

### Вход без подвисаний (кэш ключей Mojang/Xbox)

**Зачем.** До кэша первый вход после рестарта мог ждать 20–30+ с на HTTP к `client.discovery.minecraft-services.net` и JWKS, блокируя воркеры и создавая ощущение «сервер завис».

**Где лежит кэш.** `<dataPath>/auth_keys_cache.json` (путь задаётся в `Server` при создании `AuthKeyProvider`).

**Как работает.**

| Этап | Поведение |
|---|---|
| Старт сервера | `AuthKeyProvider::loadFromCache()` читает JSON в память (<0.001 с) |
| Первый join | JWT проверяется локальными ключами — **без** ожидания сети |
| Фон | `FetchAuthKeysTask` подтягивает обновления ключей; не блокирует main thread |
| Сеть недоступна | Используются ключи из кэша; таймаут cURL **4.0 с** в `fetchURL()` не «вешает» пул |

**Практика.**

- Бэкапьте `auth_keys_cache.json` вместе с миром; при полной потере кэша первый вход снова зависит от Mojang API.
- Мониторьте логи `FetchAuthKeysTask` при деградации DNS.

### Пул async-воркеров

**Зачем.** Сериализация чанков, zlib, JWT, генерация — CPU-heavy; на main thread это режет TPS.

**Как устроено.** `processors = max(1, Utils::getCoreCount() - 2)` — число воркеров привязано к ядрам CPU (минус пара под ОС/главный поток).

**Что уходит в фон (типично).** подготовка `LevelChunkPacket`, compress batch, часть крипто-проверок, генерация terrain populate.

**Ограничения.** Воркеры не заменяют оптимизацию плагинов: тяжёлые циклы в `onTick` по-прежнему бьют по TPS.

## Сеть и протокол

### Кодирование пакетов по `protocolId`

**Зачем.** Bedrock меняет layout полей между патчами; один binary buffer для всех клиентов даёт decode error и kick.

**Контракт API.**

```php
$packet->encode($out, $session->getProtocolId());
$packet->decode($in, $session->getProtocolId());
```

Внутри — `encodePayload` / `decodePayload` с ветвлением по `$protocolId`.

**Примеры версионных различий (не исчерпывающий список).**

| Пакет | Что меняется между версиями |
|---|---|
| `LevelSoundEventPacket` | VarInt id → string id с 1.26.30+; `firePosition` с 1.26.20+ |
| `SubChunkPacket` / `SubChunkRequestPacket` | legacy VarInt vs фиксированные координаты с 1.26.30/40 |
| `PlayerListPacket` | legacy до 1.26.30; `playFabId` с 1.26.60+ |
| `AddPlayerPacket` / `AddActorPacket` | `passengerBlockData` с 1.26.60+ |
| `MovePlayerPacket` | `telemetryData` с 1.26.40+ |
| `PlaySoundPacket` | `serverSoundHandle`, `loopCount`, `playbackPositionSeconds` по патчам |
| `ClientCacheBlobStatusPacket` | порядок hit count ≤1.26.20 vs ≥1.26.30 |

При добавлении нового Bedrock-патча обновляются `bedrock-protocol` + соответствующие `encodePayload` ветки.

### Чанки, блоки, предметы

- `ChunkCache` — ключ `(chunkHash, protocolId)` для промисов сжатия и готовых буферов.
- `BlockTranslator` / `ItemTranslator` внутри `TypeConverter` — runtime id и NBT метаданные **для получателя**.
- `Server::prepareBatch($buffer, $protocolId, ...)` — сжатие исходящего батча под конкретный протокол.

### Широковещание

`StandardPacketBroadcaster`: для пакета собираются группы игроков с одинаковым `protocolId`, буфер кодируется **N раз** (по числу групп), не по числу игроков.

### Мульти-транспорт (обзор)

| Параметр | Значение |
|---|---|
| Максимум транспортов | `Server::MAX_ACTIVE_TRANSPORTS = 8` |
| NetherNet | WebRTC, signaling TCP + ICE UDP (`ext-webrtc`) |
| RakLib | UDP RakNet (dual или fallback) |
| Пробуждение | IPC `TimeTrackingSleeperHandler` между I/O и главным циклом |

Детальная эксплуатация NetherNet — в разделе «Мультиверсия, NetherNet и resource packs» и встроенном гайде ниже.

## Мир и геометрия

### Воксельные формы (VoxelShapes)

**Зачем.** Bedrock 1.26+ отдаёт клиенту data-driven хитбоксы/формы блоков; сервер должен прислать те же структуры, что в bedrock-data.

**Как устроено.** `StaticPacketCache` кэширует `JigsawStructureDataPacket`, `VoxelShapesPacket`, палитру блоков; `PreSpawnPacketHandler` отправляет их до `StartGamePacket`.

**Модели в коде.** `VoxelShapeData`, `VoxelShapesData`, `VoxelShapeCellsData` в `pocketmine\network\mcpe\cache\model`.

**Практика.** Для кастомных блоков используйте публичные block API; не дублируйте voxel packets вручную без необходимости.

### Генератор `void`

**Зачем.** Арены DbD/мини-игр без ванильного террейна — минимальная нагрузка на генерацию и I/O.

**Как включить.** `/world create arena 0 void` или API `MultiWorldModule::resolveGenerator("void")`. Регистрация — `VoidGenerator` в `GeneratorManager`.

## API

Ниже — **публичные сигнатуры**, затронутые мультипротокольностью. Для примеров вызова см. раздел «Мультиверсия…» и `docs/core-updates.md`.

### `pocketmine\network\mcpe\handler`

- `SessionStartPacketHandler::isCompatibleProtocol(int $protocolVersion) : bool` — единственная точка «пустить / нет» по protocol id на раннем этапе сессии.

### `pocketmine\network\mcpe\protocol`

- `ProtocolInfo::ACCEPTED_PROTOCOL` — `list<int>` допустимых протоколов.
- `DataPacket::decode(ByteBufferReader $in, int $protocolId)` / `encode(...)` — обёртки; реализация в `decodePayload` / `encodePayload`.

**Пример для плагина с кастомным пакетом (осторожно):**

```php
$pid = $player->getNetworkSession()->getProtocolId();
$pk = new MyPacket();
$player->getNetworkSession()->sendDataPacket($pk); // сессия вызовет encode с верным $pid
```

### `pocketmine\network\mcpe\convert`

```php
$tc = TypeConverter::getInstance($player->getNetworkSession()->getProtocolId());
$protocol = $tc->getProtocolId();
```

### `pocketmine\network\mcpe\cache`

```php
$chunk = $server->getChunkCache()->request($x, $z, $typeConverter);
```

## Возможности ядра (capabilities)

### Зачем

Плагины часто делают `class_exists` / reflection по внутренностям ядра. Это ломается при рефакторинге. **Capabilities** — явный контракт: «на этом билде есть фича X».

### Как пользоваться

В `plugin.yml` плагин может потребовать набор id. Если чего-то нет — плагин **не загрузится** (ошибка в логе):

```yaml
requires-capabilities:
  - form-api
  - camera-instruction
  - multiworld-commands
```

В коде:

```php
$caps = $server->getCapabilities();
if($caps->has("nethernet")){
	// можно опираться на NetherNet
}
$all = $caps->getAll(); // list<string>
```

### Зарегистрированные id (сейчас)

`folder-plugins`, `folder-packs`, `nethernet`, `session-record`, `adaptive-qos`, `world-clone`, `multiworld-commands`, `multiworld-module`, `worldedit`, `form-api`, `plugin-data-version`, `xuid-playerdata`, `unknown-item`, `tick-freeze`, `prometheus-metrics`, `camera-instruction`, `unknown-block`, `movement-guard`, `datapacks`, `plugin-security-scan`.

Новые релизы добавляют id при старте сервера в `Server` (register рядом с остальными).

## Мультиверсия, NetherNet и resource packs (база)

### Multi-version Bedrock

**Зачем.** На одном сервере могут сидеть клиенты разных патчей Bedrock (1.20 … 1.26.60). Без multi-version старые клиенты отваливаются на handshake.

**Как устроено.** Список версий в `ProtocolInfo::ACCEPTED_PROTOCOL`. На старте сессии `SessionStartPacketHandler::isCompatibleProtocol()` решает, пускать ли протокол. Дальше пакеты и чанки кодируются **под протокол конкретного игрока** (TypeConverter / ChunkCache по protocol id).

**Как пользоваться.** Обычно ничего настраивать не нужно — достаточно актуального ядра. Плагины, которые шлют сырые пакеты из `pocketmine\network\mcpe`, сами отвечают за совместимость версий; публичный API Player/World безопаснее.

### NetherNet (WebRTC-транспорт)

**Зачем.** С Bedrock 1.26.60 клиенты уходят с чистого RakNet на NetherNet (WebRTC). Ядро умеет держать **оба** транспорта сразу, чтобы мигрировать постепенно.

**Как устроено.** В `pocketmine.yml` секция `transport:`. При наличии `ext-webrtc` поднимается NetherNet (signaling TCP + ICE UDP). Без расширения сервер логирует пропуск и остаётся на RakNet.

**Как пользоваться.**

```yaml
transport:
  name: nethernet,raknet   # dual на время миграции
```

- Нужен PHP с `ext-webrtc` (сборки axolotl-pm/PHP-Binaries).
- Ключ идентичности: `nethernet.key` (создаётся сам). **Бэкапить** — смена ключа заставляет игроков заново подтверждать trust (TOFU).
- Firewall: TCP signaling (`server-port` / builtin-signaling.port) + UDP ICE range; LAN discovery UDP 7551.
- STUN в шаблоне есть; для жёсткого NAT нужен TURN.
- Подробно: `docs/nethernet.md`.

Capability: `nethernet`.

#### Справочник: NetherNet (эксплуатация)

NetherNet — WebRTC-транспорт Bedrock вместо чистого RakNet (с клиента 1.26.60 / v26.60 RakNet снят).

##### Требования

1. PHP с `ext-webrtc` ([axolotl-pm/PHP-Binaries](https://github.com/axolotl-pm/PHP-Binaries)).
2. В `pocketmine.yml` → `transport.name` содержит `nethernet` (по умолчанию в шаблоне часто только `nethernet`; dual — `nethernet,raknet`).
3. Firewall / проброс:
   - **TCP** — signaling (`server-port` из `server.properties` или `transport.nethernet.builtin-signaling.port`);
   - **UDP** — ICE media (`transport.nethernet.port-range` или ephemeral);
   - **UDP 7551** — LAN discovery при встроенном signaling.

Без `ext-webrtc` сервер пишет, что NetherNet пропущен, и работает на других транспортах (например RakNet).

##### Ключ идентичности

`transport.nethernet.key-file` (по умолчанию `nethernet.key`) создаётся при первом старте.

- **Сохраняйте в бэкап.** Смена/удаление = повторный trust (TOFU) у игроков.
- Права файла: `0600`.

##### STUN / TURN

В шаблоне есть публичный STUN для лёгкого NAT.

| Сценарий | Рекомендация |
|---|---|
| Домашний / лёгкий NAT | STUN часто достаточно |
| Symmetric NAT / CGNAT / мобильный интернет | Нужен **TURN** (`type: turn` + login) |
| TURN + `ice-udp-mux` | **Не** включать вместе |

##### TLS и reverse proxy

Plain HTTP signaling → диалог доверия у клиента при первом входе. Boot NOTICE для plain HTTP убран (только `debug`; тишина при `reverse-proxy.enabled`).

Для production:

1. Caddy/Nginx/Cloudflare с валидным сертификатом перед TCP signaling **или** `transport.nethernet.builtin-signaling.tls.{certificate,key,passphrase}`.
2. При reverse proxy: `reverse-proxy.enabled: true`, заголовок forwarded IP, `trusted-ips`.

##### Миграция dual transport

По умолчанию `transport.name: nethernet`. Для старых клиентов/утилит: `nethernet,raknet`. Query имеет отдельный UDP-путь, когда RakNet выключен.

##### Transfer между серверами

`Player::transfer($host, $port)` шлёт Bedrock `TransferPacket`. Для NetherNet-цели `host:port` — **signaling** endpoint (TCP). Полный seamless WebRTC handoff между инстансами здесь не документирован.

Полный конфиг: секция `transport:` в `resources/pocketmine.yml` и живой `pocketmine.yml`. Документ: `docs/nethernet.md`.

## Adaptive QoS и запись сессий

### Adaptive QoS

**Зачем.** На высоком ping клиент «не успевает» за чанками/сущностями → резинка, таймауты. Временно **урезать view distance** слабым каналам дешевле, чем кикать.

**Как устроено.** `AdaptiveQosManager` смотрит EWMA ping игрока, держит soft/hard пороги и hysteresis (чтобы дистанция не дёргалась каждый тик). Эффективный радиус никогда не поднимается выше того, что запросил клиент/плагин и что позволяют memory limits.

**Как пользоваться.**

```yaml
network:
  adaptive-qos:
    enabled: true
    ping-soft-ms: 150
    ping-hard-ms: 300
    recover-ms: 100
    soft-view-distance: 6
    hard-view-distance: 4
    min-view-distance: 3
    check-interval-ticks: 40
```

По умолчанию **выключено** — включайте после теста на своей базе.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `enabled` | `false` | Включить `AdaptiveQosManager` |
| `ping-soft-ms` | `150` | Мягкий порог: cap = `soft-view-distance` |
| `ping-hard-ms` | `300` | Жёсткий порог: cap = `hard-view-distance` |
| `recover-ms` | `100` | Гистерезис перед возвратом дистанции |
| `soft-view-distance` | `6` | Дистанция на soft-уровне |
| `hard-view-distance` | `4` | Дистанция на hard-уровне |
| `min-view-distance` | `3` | Нижний предел |
| `check-interval-ticks` | `40` | Как часто пересчитывать EWMA ping |

**Поведение:** клиент запрашивает радиус → сохраняется как desired; QoS может снизить effective distance через `Player::applyQosViewDistance()`; при улучшении ping дистанция возвращается к desired, но не выше лимитов памяти и запроса клиента.

Capability: `adaptive-qos`. Документация: `docs/adaptive-qos.md`.

#### Справочник: поведение Adaptive QoS

При сглаженном (EWMA) ping выше порога сервер **временно** снижает view distance игрока — меньше чанков и сущностей в исходящем трафике, меньше rubberband на слабых каналах.

**Уровни.**

- **soft:** ping ≥ `ping-soft-ms` → effective cap = `soft-view-distance`
- **hard:** ping ≥ `ping-hard-ms` → effective cap = `hard-view-distance`
- **recover:** `recover-ms` — гистерезис, чтобы дистанция не дёргалась каждый тик
- Никогда не поднимать effective выше desired (запрос клиента/плагина) и выше memory limits

**Пошагово.**

1. Клиент запрашивает радиус → сохраняется desired.
2. `AdaptiveQosManager` пересчитывает EWMA на `check-interval-ticks`.
3. `Player::applyQosViewDistance()` применяет cap.
4. При улучшении ping — плавный возврат к desired.

По умолчанию **выключено** — включайте после A/B на своей аудитории. Документ: `docs/adaptive-qos.md`.

### Запись сессий (Session Recorder)

Запись игровой сессии в append-only **JSONL** для разбора жалоб, forensics и лёгкого anticheat-aid. Это **не** полноценный packet-demo / клиентский replay: семплы событий (движение, чат, урон, инвентарь и т.д.), без сырых payload пакетов. Полный гайд: `docs/session-recording.md`.

#### Быстрый старт

1. В `pocketmine.yml` включить запись:

```yaml
session-recording:
  enabled: true
  auto-record-all: false
  directory: session_recordings
  move-sample-ticks: 5
  record-packet-ids: false
  max-file-mb: 64
```

2. Перезапустить сервер (менеджер читает конфиг при старте).

3. Записать конкретного игрока:

```text
/sessionrecord start CandyDev
/sessionrecord status
/sessionrecord stop CandyDev
```

Право: `pocketmine.command.sessionrecord` (по умолчанию у ops).

Если `enabled: false`, команда откажется стартовать запись.

---

#### Где хранятся файлы

Корень — относительно **data path** сервера (в Docker обычно `/data` = корень проекта):

```text
<dataPath>/<directory>/<Ник>/
```

По умолчанию:

```text
session_recordings/
  CandyDev/
    2026-11-07_204300_2535421306486693.jsonl
    2026-11-07_211500_2535421306486693.jsonl
  OtherPlayer/
    2026-11-07_220000.jsonl
```

| Часть пути | Смысл |
|---|---|
| `session_recordings/` | Каталог из `session-recording.directory` |
| `<Ник>/` | Папка игрока (небезопасные символы ника заменены на `_`) |
| `YYYY-mm-dd_HHMMSS[_xuid].jsonl` | Одна сессия: дата/время старта; XUID добавляется, если есть |

Ник в имени файла **не** дублируется — он уже в названии папки. Внутри JSON (`session_start`) ник и путь к файлу всё равно пишутся.

Старые записи, лежавшие плоско в корне `session_recordings/*.jsonl`, автоматически не переносятся.

#### Конфиг (`pocketmine.yml`)

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `enabled` | `false` | Включить менеджер и слушатели; без этого `/sessionrecord` не стартует |
| `auto-record-all` | `false` | Автостарт записи на каждый `PlayerJoin` |
| `directory` | `session_recordings` | Относительный каталог под data path |
| `move-sample-ticks` | `5` | Как часто **проверять** позицию (в тиках сервера). `0` — не писать `move` |
| `record-packet-ids` | `false` | Писать `packet_in` (имя + pid входящего пакета, **без** тела). Может сильно раздувать файл |
| `max-file-mb` | `64` | Лимит размера файла; при достижении — `limit_reached` и запись останавливается |

##### Движение без спама

Сэмпл `move` пишется **только если изменилась поза**: `x`, `y`, `z`, `yaw`, `pitch` или `world` (после округления).  
Стояние на месте не засоряет JSONL одинаковыми строками. Интервал `move-sample-ticks` лишь ограничивает частоту проверки.

#### Команды

| Команда | Действие |
|---|---|
| `/sessionrecord start <игрок>` | Начать запись (reason: `command`) |
| `/sessionrecord stop <игрок>` | Остановить (reason: `command`) |
| `/sessionrecord status` | Список игроков, у которых запись активна сейчас |

Автоостановка:

- выход игрока → `session_end` с reason `quit`;
- выключение сервера → reason `shutdown`.

Одновременно у одного игрока может быть только одна активная запись.

#### Формат JSONL

Каждая строка — один JSON-объект:

```json
{"ts": 1794073416.195433, "type": "move", "x": 261.367, "y": 70, "z": 259.79, "yaw": 181.9, "pitch": 3.63, "world": "lobby"}
```

- `ts` — Unix-время с дробной частью (`microtime(true)`);
- `type` — тип события;
- остальные поля — payload конкретного типа.

##### Типы событий

#### `session_start`

Старт записи.

| Поле | Описание |
|---|---|
| `reason` | `command`, `auto`, `manual`, … |
| `player` | Ник |
| `xuid` | Xbox User ID (может быть пустым) |
| `uuid` | UUID игрока |
| `protocol` | Protocol id клиента |
| `ip_hash` | SHA-256 от `IP\|UUID` (**сырой IP не пишется**) |
| `file` | Абсолютный/полный путь к этому JSONL |

#### `session_end`

| Поле | Описание |
|---|---|
| `reason` | `quit`, `command`, `shutdown`, … |
| `ping_ms` | Последний ping или `null`, если уже отключён |

#### `move`

| Поле | Описание |
|---|---|
| `x`, `y`, `z` | Координаты (округление до 3 знаков) |
| `yaw`, `pitch` | Углы (до 2 знаков) |
| `world` | Имя папки мира |

Пишется только при изменении позы (см. выше).

#### `ping`

| Поле | Описание |
|---|---|
| `ms` | RTT в миллисекундах |

Не чаще одного раза в секунду на игрока (из `NetworkSession::updatePing`).

#### `chat`

| Поле | Описание |
|---|---|
| `message` | Текст сообщения |

#### `interact`

Клик / использование предмета по блоку.

| Поле | Описание |
|---|---|
| `action` | Код действия `PlayerInteractEvent` |
| `x`, `y`, `z` | Пол блока |
| `item` | Имя предмета в руке |

#### `drop`

| Поле | Описание |
|---|---|
| `item` | Имя предмета |
| `count` | Количество |

#### `inventory_open` / `inventory_close`

| Поле | Описание |
|---|---|
| `inventory` | FQCN класса инвентаря |

#### `damage`

Пишется для жертвы и/или атакующего, если это игроки с активной записью.

| Поле | Описание |
|---|---|
| `cause` | Причина урона |
| `damage` | Финальный урон |
| `role` | `victim` или `attacker` |
| `attacker` | (для victim) ник или класс сущности |
| `victim` | (для attacker) ник или класс сущности |

#### `packet_in` (опционально)

Только при `record-packet-ids: true`.

| Поле | Описание |
|---|---|
| `name` | Имя пакета |
| `pid` | Packet id |

Тело пакета **не** сохраняется.

#### `limit_reached`

Файл достиг `max-file-mb`. Дальнейшая запись в этот sink прекращается.

| Поле | Описание |
|---|---|
| `max_file_mb` | Лимит из конфига |

---

#### Как это работает внутри

1. При `enabled: true` `SessionRecordingManager` регистрирует MONITOR-слушатели (чат, interact, drop, инвентарь, урон, join/quit; опционально входящие пакеты).
2. `start()` создаёт папку игрока, открывает `JsonlSessionSink` и кладёт сессию в активные.
3. События вызывают запись **только** если для этого игрока есть активная сессия (иначе no-op).
4. Каждый тик сервера менеджер семплит `move` у активных записей.
5. `stop` / quit / shutdown пишут `session_end` и закрывают файл.

Ключевые классы:

| Класс | Роль |
|---|---|
| `SessionRecordingManager` | Конфиг, start/stop, слушатели, тик |
| `ActiveSessionRecording` | Одна активная сессия + дедуп `move` |
| `JsonlSessionSink` | Append-only запись и лимит размера |
| `SessionRecordCommand` | `/sessionrecord` |

---

#### Ограничения и практика

- Не заменяет anticheat и не восстанавливает картинку «как на клиенте».
- При `auto-record-all: true` диск и I/O растут быстро — держите разумный `max-file-mb` и ротацию/архивацию папок вручную.
- `record-packet-ids: true` ещё сильнее раздувает файлы; для обычного разбора жалоб обычно не нужен.
- IP в открытом виде нет; есть только `ip_hash`.
- Слушатели при `enabled: true` зарегистрированы всегда; без активной записи события игрока в файл не попадают.

## Resource packs (расширенные)

Конфиг: `resource_packs.yml`.

#### Справочник: форматы и доставка паков

##### Форматы

| Формат | Поведение |
|---|---|
| `.zip` / `.mcpack` | Загрузка как есть |
| Папка с `manifest.json` | Авто-zip в `compress_cache_dir`; оригинал в `resource_packs/` **не** меняется |

##### Стеки

| Ключ YAML | Назначение |
|---|---|
| `resource_stack` | Глобальный стек по умолчанию |
| `world_stacks.<папка_мира>` | Стек при логине, если настроен для default world folder |
| `named_stacks.<имя>` | Именованные стеки для плагинов |

**Важно:** Bedrock **не** меняет resource packs в активной сессии. После `/resourcepacks reload` или смены стека игрок должен **перезайти**.

##### CDN

```yaml
cdn_urls:
  <pack-uuid-or-filename>: "https://cdn.example.com/pack.zip"
```

URL в `ResourcePacksInfoPacket`. Локальные копии оставляйте для fallback. Плагин: `PlayerResourcePackOfferEvent::setCdnUrls()`.

##### Unchanged packs / клиентский кэш

Нет binary-diff протокола. Клиент пропускает скачивание при совпадении **UUID + version**.

- Кэш сжатия folder/zip сбрасывается по mtime.
- При reload сервер логирует смену fingerprint `uuid|version|sha256`.
- Мелкая правка текстур → поднимите `version` в `manifest.json`, UUID оставьте.

```php
$fp = $rpm->getPackContentFingerprint($pack); // uuid|version|sha256hex
```

##### Шифрование

- Файл `<pack>.key` рядом (ровно **32 байта**), или в стеке `{pack, key_file}`.
- Успех: лог `Encrypted resource pack "..."`.
- Ошибка ключа: warning.

##### Hot-reload

```text
/resourcepacks reload
```

Permission: `pocketmine.command.resourcepacks`. YAML и паки с диска; онлайн-игроки не обновятся без reconnect.

##### Параметры отправки

`pack_chunk_size_kb`, `pack_chunk_concurrency` — размер и параллельность чанков при стриминге пакета клиенту.

Документ: `docs/resource-packs.md`.

### World / named stacks

**Зачем.** У лобби один набор паков, у арены — другой. Глобальный `resource_stack` недостаточен.

**Как устроено.**

- `world_stacks.<имя_папки_мира>` — стек для мира.
- `named_stacks.<имя>` — именованные стеки для плагинов.
- На логине клиенту предлагается стек **дефолтного** мира (если задан), иначе глобальный.

```php
$rpm = $server->getResourcePackManager();
$stack = $rpm->getResourceStackForWorld("arena");
$named = $rpm->getNamedStack("pvp_ui");
```

**Важно.** Bedrock **не умеет** горячо менять resource packs mid-session. После смены стека / `/resourcepacks reload` игрокам нужен **reconnect**.

---

### CDN (#10)

**Зачем.** Тяжёлые паки выгоднее качать с CDN, а не чанками с игрового сервера.

```yaml
cdn_urls:
  "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx": "https://cdn.example.com/pack.zip"
  "lobby_textures.zip": "https://cdn.example.com/lobby_textures.zip"
```

URL уходят в `ResourcePacksInfoPacket`. Локальные паки лучше оставлять как fallback. Плагины могут переопределить через `PlayerResourcePackOfferEvent::setCdnUrls()`.

---

### Unchanged packs / client cache (#11)

**Зачем.** Не гонять повторную закачку, если контент не менялся.

**Как устроено.** Клиент кэширует по **UUID + version**. Ядро считает fingerprint `uuid|version|sha256` и при reload пишет в лог, если fingerprint изменился. Кастомный binary-diff протокол **не** внедрялся.

Практика: мелкий правка текстур → bump `version` в `manifest.json`, UUID оставить.

```php
$fp = $rpm->getPackContentFingerprint($pack); // uuid|version|sha256hex
```

---

### Encryption UX (#13)

**Зачем.** Защищённые паки (ключ 32 байта) без боли в конфиге.

- Файл `<pack>.key` рядом с паком, **или**
```yaml
resource_stack:
  - pack: secret.zip
    key_file: secret.zip.key
```

Успех логируется (`Encrypted resource pack "..."`). Битый/неподходящий ключ — warning.

---

### Hot-reload (#14)

```text
/resourcepacks reload
```

Permission: `pocketmine.command.resourcepacks`.  
Перечитывает манифесты/стеки с диска. Уже залогиненные игроки **не** получают новый стек, пока не перезайдут.

### API WorldManager

```php
$wm = $server->getWorldManager();

$wm->isWorldLoaded("arena");
$wm->isWorldGenerated("arena"); // похоже на мир на диске
$wm->getWorldFolderNames();
$wm->getWorldPath("arena");
```

### Smart chunk unload

**Зачем.** Экономия RAM на больших картах / многих мирах: неиспользуемые чанки уходят в unload с политикой idle.

```yaml
chunk-ticking:
  unload:
    enabled: true
    max-chunks-per-tick: 16
    idle-ticks: 200   # ~10 с при 20 TPS
```

Spawn-чанки и чанки с viewers/loaders не выгружаются. Грязные чанки сохраняются при autosave. Более агрессивный unload = меньше RAM, но возможна задержка при возврате игрока.

Встроенный пустой генератор для арен (`GeneratorManager`). Создаёте мир с generator `void` — без террейна ваниллы.

### Soft reload (#29 lite)

```text
/plugin reload <name>
```

Alias `/plm`, permission `pocketmine.command.plugin`.

## Безопасность и эксплуатация

### Abuse limits (#39)

**Зачем.** Спам чата/команд без мгновенного kick (kick часто обходят / вредят UX). Soft token-bucket: дроп действия + предупреждение.

```yaml
abuse-limits:
  chat:
    enabled: true
    max-per-second: 2
    burst: 4
  commands:
    enabled: true
    max-per-second: 4
    burst: 8
```

Консоль не лимитируется. Warn throttling ~2 с (чтобы не заспамить лог). Отдельные лимиты batch пакетов по-прежнему свои.

### Crash dump scrubbing (#42)

**Зачем.** В crash report легко утекает `rcon.password`, токены БД, argv.

**Как устроено.** Перед включением настроек/phpinfo/argv в дамп строки с password/secret/token/… заменяются на `******` (`CrashDumpScrubber`).

Рекомендация: в проде держать `auto-report.send-phpinfo: false`.

### Healthcheck (#51)

**Зачем.** Docker/K8s должны понимать, жив ли процесс и не в drain ли он.

Пока сервер работает, каждую секунду пишется `health.status` в data-dir:

```text
ok <tick> <unix_ts>
```

При shutdown/drain:

```text
stopping <unix_ts>
```

`Dockerfile` / `docker-compose` используют `/usr/local/bin/docker-healthcheck.sh`.  
K8s exec: тот же скрипт + путь к файлу + freshness (по умолчанию 15 с, строка должна начинаться с `ok `).

### Soft shutdown / drain (#54)

**Зачем.** Жёсткий kill рвёт сохранения и матчи. Drain даёт игрокам время выйти / доиграть до дедлайна.

```yaml
shutdown:
  drain-seconds: 10   # 0 ≈ сразу как раньше
```

На SIGTERM / `/stop`:

1. Режим drain, health → `stopping`, короткое сообщение игрокам  
2. Новые логины отклоняются («Server is shutting down»)  
3. Тики продолжаются, пока нет игроков **или** вышло время  
4. Затем обычный `forceShutdown()` (kick остатка, save, unload)

В логе — старт/конец drain с числом игроков.

### Clearer logs (#53)

#### Справочник: durable save, movement, light, metrics, scan

##### Надёжная запись малых файлов

```yaml
world:
  save:
    fsync: true
    region-fsync: false
```

`Filesystem::safeFilePutContents`: temp → fflush → fsync → rename. Ban list, install `.phar`, `level.dat` path.

##### Tick freeze

```text
/tick freeze|unfreeze|step [n]|query
```

Permission: `pocketmine.command.tick`. Freeze останавливает тики миров и plugin scheduler; сеть, консоль, health, drain, metrics — работают.

##### Prometheus

```yaml
metrics:
  enabled: false
  file: true
  bind: ""
```

`metrics.prom` раз в секунду; опционально `GET /metrics`. Гистограммы: `pmmp_tick_duration_seconds`, `pmmp_world_tick_duration_seconds`; `pmmp_world_leveldb_flush_age_seconds` при sidecar.

##### Sidecar LevelDB

```yaml
world:
  save:
    leveldb-sidecar: true
```

`worlds/<name>/db/LAST_FLUSH` после batch write (JSON `{unix,tick,chunk_x,chunk_z}`). **Не WAL**, не replay после краша — только мониторинг.

##### Movement guard

```yaml
player:
  movement:
    enabled: true
    max-blocks-per-move: 15
    max-blocks-per-tick: 10.0
    send-prediction-correction: true
```

Rubberband + опционально `CorrectPlayerMovePredictionPacket`. Не полный server-auth AC.

##### Отложенный свет

```yaml
world:
  light:
    defer-updates: true
```

Коалесcing до конца тика мира; populate async (`LightPopulationTask`, соседи 3×3).

##### Security scan

```yaml
plugins:
  security-scan: true
  security-scan-mode: warn
```

Скан `.php`, `.phar`, `.zip` на опасные вызовы. Не OS sandbox. См. `resources/php.ini.recommended`.

Документ: `docs/ops.md`.


Меньше шума: rate-limit warn один раз в окне; drain с явными строками; пер-сессионный PrefixedLogger для disconnect-шума.

## Игрок, UI и данные

### FormAPI (#45)

**Зачем.** Единые формы в ядре (`pocketmine\form\*`), без обязательной зависимости от сторонних FormAPI. MiniGameBase-формы остаются для старых плагинов.

```php
use pocketmine\form\SimpleForm;
use pocketmine\form\ModalForm;
use pocketmine\form\CustomForm;

$form = new SimpleForm(function(Player $player, mixed $data) : void{
	// $data: int (индекс кнопки) или null (закрыл крестиком)
});
$form->setTitle("Магазин")
	->setContent("Выбери")
	->addButton("Купить")
	->addButton("Отмена");
$form->send($player);
```

- `ModalForm` — две кнопки + текст  
- `CustomForm` — `addInput` / `addToggle` / `addSlider` / `addDropdown` / `addLabel` / `addStepSlider`  
- Невалидный ответ → `FormValidationException` в лог, без краша  

Capability: `form-api`.

JSON-формы (`ModalForm` / `CustomForm` через `sendForm`) **закрываются** на каждое действие клиента. Для **реактивного UI** без пересборки см. раздел **Data-Driven UI**.

### Plugin data-version (#50)

**Зачем.** При обновлении плагина нужно один раз смигрировать `plugin_data/`.

```yaml
# plugin.yml
data-version: 2
```

Или override `PluginBase::getPreferredDataVersion()` / `migrateData(int $from, int $to)`.  
Версия хранится в `plugin_data/<Plugin>/data-version`. `0` = проверка выключена.

Capability: `plugin-data-version`.

### XUID player files (#47 lite)

**Зачем.** Ник можно сменить; XUID (Xbox) стабильнее. Без dual-write смена ника = «новый» инвентарь / потеря прогресса.

**Как устроено.** При authenticated save пишутся оба файла:

- `players/<name>.dat`  
- `players/xuid/<xuid>.dat`  

Load сначала ищет XUID-файл, потом name. Offline / без XUID — как раньше по имени.

Capability: `xuid-playerdata`. Полный SQL/Redis store — в этом релизе не добавлялось.

### UnknownItem (#49 lite)

**Зачем.** Кастомный/будущий предмет из мира или инвентаря не должен превращаться в воздух при save.

Неизвестный тип → `UnknownItem` с сохранённым `SavedItemData`; при записи тип восстанавливается. На клиенте может отображаться как info_update. Стак = 1 (чтобы не склеивать разные unknown).

Capability: `unknown-item`. Unknown **block** palette — см. раздел «Камера, движение, datapacks и unknown-блоки».

## Прочность сохранений, tick freeze и метрики

### Durable small-file save (#48 lite)

**Зачем.** `file_put_contents` при полном диске может обрезать файл. Temp + rename безопаснее; fsync уменьшает окно «данные ещё в page cache».

```yaml
world:
  save:
    fsync: true           # safeFilePutContents: fflush + fsync temp перед rename
    region-fsync: false   # fsync region-файлов только на close (дороже)
```

Используется для мелких файлов (конфиги, player.dat path, banlist, install `.phar` и т.п.). LevelDB chunk batches — отдельно: sidecar `LAST_FLUSH` (см. тот же раздел и «Дополнительные срезы платформы»).

### Tick freeze (#59)

**Зачем.** Отладка матчей / воспроизведение бага: остановить игровой тик, но оставить сеть и консоль.

```text
/tick freeze
/tick step 5
/tick query
/tick unfreeze
```

Permission: `pocketmine.command.tick`.  
Пока freeze: **не** тикают миры и plugin schedulers. Сеть, консоль, health, drain, metrics — работают. `step N` прогоняет N тиков и снова freeze.

Capability: `tick-freeze`.

### Prometheus metrics (#52 lite)

**Зачем.** Наблюдаемость TPS/игроков/памяти/миров без сторонних плагинов.

```yaml
metrics:
  enabled: true
  file: true              # пишет metrics.prom раз в секунду
  bind: "127.0.0.1:9090"  # опционально GET /metrics
```

Gauges: TPS, tick usage, players, memory, tick counter, freeze, per-world chunks/entities/tick-ms.  
Гистограммы: `pmmp_tick_duration_seconds`, `pmmp_world_tick_duration_seconds` (фиксированные бакеты).

Capability: `prometheus-metrics`. Docs: `docs/ops.md`.

## Камера (база) и PHPUnit

### Camera shake / fade / clear

**Зачем.** Плагинам нужны cutscene / hit feedback / затемнение без ручной сборки пакетов.

```php
use pocketmine\color\Color;
use pocketmine\network\mcpe\protocol\CameraShakePacket;

$player->shakeCamera(0.5, 2.0); // intensity, duration sec; TYPE_ROTATIONAL по умолчанию
$player->shakeCamera(1.0, 1.0, CameraShakePacket::TYPE_POSITIONAL);
$player->stopCameraShake();

$player->fadeCamera(0.5, 1.0, 0.5);                    // чёрный
$player->fadeCamera(0.3, 0.5, 0.3, new Color(255, 0, 0));
$player->clearCamera();
```

Внутри: `CameraShakePacket` / `CameraInstructionPacket` через `NetworkSession`.  
Capability: `camera-instruction`. Ручной smoke на Bedrock: shake → fade → clear.

### PHPUnit helpers (#60 lite)

Unit-тесты без живого Server: `AbuseRateLimiter`, `CrashDumpScrubber`, `SimpleForm`, `Filesystem::safeFilePutContents`, `UnknownItem` под `tests/phpunit/`.

## Камера, движение, datapacks и unknown-блоки

### Camera full (presets / set / FOV / target)

Расширение базовой камеры до управления через instruction/presets:

```php
use pocketmine\network\mcpe\protocol\types\camera\CameraPreset;
use pocketmine\network\mcpe\protocol\types\camera\CameraSetInstruction;
use pocketmine\network\mcpe\protocol\types\camera\CameraFovInstruction;
use pocketmine\network\mcpe\protocol\types\camera\CameraTargetInstruction;

$player->sendCameraPresets(/* CameraPreset ...$presets */);
$player->setCamera($setInstruction);
$player->setCameraFov($fovInstruction);
$player->setCameraTarget($targetInstruction);
$player->setCameraTarget(null, true); // removeTarget
```

Типы инструкций — из BedrockProtocol (`vendor/.../types/camera/`).  
**Ещё нет:** aim-assist пакеты, spline keyframe DSL — их можно слать вручную через `NetworkSession::sendDataPacket`, но first-class API нет.

### Movement guard (#44 lite)

**Зачем.** Жёсткий лимит «15 блоков за один movement» был захардкожен. Нужны конфиг и доп. лимит горизонтали за тик, чтобы резать явный телепорт-чит без полного prediction-AC.

```yaml
player:
  movement:
    enabled: true
    max-blocks-per-move: 15    # один PlayerAuthInput
    max-blocks-per-tick: 10.0  # горизонталь за processMostRecentMovements
```

При нарушении — `revertMovement` / `MovePlayerPacket::MODE_RESET` (резинка) + debug в лог сессии. Creative/spectator для per-tick check пропускаются.

Capability: `movement-guard`.  
**Это не** server-authoritative physics и не `CorrectPlayerMovePrediction` loop.

---

### Unknown block palette (#49)

**Зачем.** Как UnknownItem, но для блоков в чанках: неизвестный state не должен навсегда стать `info_update` при save.

**Как устроено.** `UnknownBlockStateStore` выделяет runtime state id и держит исходный `BlockStateData`. LevelDB deserialize при `UnsupportedBlockStateException` (и по возможности при upgrade failure) регистрирует state; serialize пишет оригинальный NBT.

Capability: `unknown-block`. Визуально на клиенте блок всё ещё может выглядеть unknown — цель именно **не потерять данные мира**.

---

### LevelDB durability sidecar (#48 lite+)

**Зачем.** В PHP-расширении LevelDB нет надёжного fsync API → полноценный WAL в ядре не сделать честно. Sidecar даёт ops-маркер «последняя успешная batch-запись».

```yaml
world:
  save:
    leveldb-sidecar: true
```

После `$db->write($batch)` обновляется `worlds/<name>/db/LAST_FLUSH` через `safeFilePutContents`. Это **не** восстанавливает чанки после краша само по себе — только след для forensics / мониторинга.

---

### Datapacks recipes (#57 lite)

**Зачем.** Добавлять рецепты без пересборки phar bedrock-data, папками на диске.

```text
datapacks/
  my_pack/
    recipes/
      shapeless_crafting.json
      shaped_crafting.json
      potion_type.json
      ...
```

Формат JSON — **тот же PM/bedrock-data**, что грузит `CraftingManagerFromDataHelper` (не vanilla Java datapack). При старте сервер мержит паки в crafting manager; ошибки пака логируются, boot не валится.

Capability: `datapacks`. Loot tables / tags / advancements — нет.

---

### Plugin security scan (#40 lite)

**Зачем.** Настоящий process-sandbox — отдельный мегапроект. Lite: перед load просканировать исходники плагина на опасные вызовы.

```yaml
plugins:
  security-scan: true
  security-scan-mode: warn   # warn | fail
```

Ищет в `.php`: `eval`, `assert`, `shell_exec`, `passthru`, `proc_open`, `pcntl_exec`, `system`, `exec`, `popen`.  
`warn` — warning в лог и загрузка продолжается; `fail` — плагин не грузится.

Capability: `plugin-security-scan`.  
Для реальной защиты: `disable_functions` / `open_basedir` в `php.ini`.

---

### TesterPlugin / phpunit (#60)

TesterPlugin на старте прогоняет ClosureTests: script plugin load, capabilities ядра, наличие camera-методов на `Player`, SimpleForm serialize.  
PHPUnit: store / MovementGuard / histogram / security scanner (+ helpers камеры).  
Полноценный deterministic gameplay harness (физика матча) — не делался.

## Дополнительные срезы платформы

Ниже — доводка функций, которые не тянут отдельный «мегапроект», но дают операторам и плагинистам измеримый эффект.

### Усиление security scan (#40)

**Зачем.** PHP не даёт настоящий process sandbox; остаётся превентивный скан исходников и hardening php.ini.

**Что добавлено.**

- `resources/php.ini.recommended` — эталон `disable_functions` / `open_basedir`.
- Boot NOTICE, если опасные функции всё ещё доступны.
- Scanner: backticks, `create_function`, `preg_replace /e`; `assert` — только при `security-scan-mode: fail`.

### Prediction correction (#44)

**Зачем.** После rubberband клиенту полезно получить коррекцию prediction, а не только `MODE_RESET`.

**Конфиг.** `player.movement.send-prediction-correction: true` → `CorrectPlayerMovePredictionPacket` при нарушении guard.

### Datapack item tags (#57)

**Зачем.** Группировка предметов для рецептов/логики без пересборки bedrock-data.

**Путь.** `datapacks/<pack>/tags/items/*.json` → `ItemTagToIdMap` (формат PM, не Java datapack).

### Legacy Anvil export (#16)

**Зачем.** Выгрузить мир в legacy Anvil для внешних инструментов.

**Команда.** `/world export-anvil <src> <dest>` через `WritableAnvil`. **Lossy**; не палитра Java 1.13+ write.

### Отложенный свет (#17)

**Зачем.** Меньше микро-стuttering при массовых block updates в тике.

**Поведение.** `world.light.defer-updates: true` (default) — coalesce до конца тика мира; счётчики execute — в Prometheus.

### Камера aim-assist / spline / attach (#43)

**API.** `sendCameraAimAssistPresets`, `sendCameraAimAssist`, `setCameraSpline`, `attachCameraToEntity`, `detachCameraFromEntity`.

**Ограничение.** Полноценный cinematic DSL частично закрыт builder'ом `CameraSplineBuilder` (см. раздел WorldEdit/DSL).

### LAST_FLUSH observability (#48)

**Метрики.** `pmmp_world_leveldb_flush_age_seconds`; в `health.status` опционально `flush_age_s:world=N`. Это возраст sidecar, **не** WAL.

## Платформенные границы и оставшиеся срезы

### Loot tables datapack

**Зачем.** Дроп с сущностей/блоков без пересборки bedrock-data.

**Путь.** `datapacks/<pack>/loot_tables/*.json` → `DatapackLootRegistry::roll($name)`. При наличии `pack.mcmeta` — notice в лог (не Java advancements).

**Ограничение.** Формат PM-native, не vanilla Java loot DSL.

### Movement correction (уточнение)

**Зачем.** Клиенту передаётся **реальная** motion при коррекции (включая flying / onGround hint), а не только reset позиции.

**Ограничение.** Это не server-auth physics loop; см. `movement-guard`.

### Свет и Anvil read

**Prometheus.** Счётчики `pmmp_light_*_execute_total` (deferred vs immediate execute).

**Anvil.** Чтение секций **Java 1.13+ paletted** (lossy, конверсия через WorldEdit Java→Bedrock). **Запись** остаётся legacy Anvil.

### Платформенные ограничения (closed)

| Тема | Статус | Что есть вместо |
|------|--------|-----------------|
| OS process sandbox | **wontfix** (PHP) | token scan + `open_basedir` + `php.ini.recommended` |
| LevelDB WAL/fsync | **wontfix** (нет API ext) | `LAST_FLUSH` JSON + age metrics |
| Vanilla Java datapacks | **wontfix** | PM recipes / tags / loot в `datapacks/` |
| Anvil 1.13+ paletted **write** | **deferred/wontfix** | legacy write + lossy palette **read** |
| Full off-thread incremental light | **wontfix** | async populate + defer + Prometheus |
| Full server-auth prediction | **wontfix** | movement-guard + velocity correction |
| Camera spline DSL | **shipped** | `CameraSplineBuilder` + named splines |

**WorldEdit entities (отложено).** Save entity в схеме, `//copy`/`//cut` с entities, rotate/flip, LoaderManager preserve-on-overwrite — не в этом релизе; lite load+paste описан выше.

## Data-Driven UI (DDUI) — Rubyx (Bedrock 1.26+)

**Зачем.** Bedrock 1.26+ умеет экраны с **общим data store**: сервер шлёт `ClientboundDataStoreUpdate`, клиент не закрывает форму. Это замена «открыть JSON CustomForm заново» для чатов, магазинов, опросов с live-полями.

**Чем не заменяет FormAPI (раздел «Игрок, UI и данные»).** Классический `CustomForm` + resource pack `server_form_post.json` (двухколоночный MineChat) — по-прежнему **ModalForm + JSON UI**. DDUI Ore UI (`minecraft:custom_form`) и **кастомные `screenId` из RP** — другой путь (см. `docs/DDUI_THEMING.md`).

### Включение

```yaml
# pocketmine.yml
ddui:
  enabled: true
  replace-delay-ticks: 20
  session-timeout-ticks: 6000
  max-inbound-updates-per-tick: 32
  max-outbound-updates-per-tick: 64
  default-theme: rubyx:classic
  themes:
    rubyx:postsystem:
      style-id: minechat:postsystem
      resource-pack: MineChat_PostSystem
```

Клиент: **протокол ≥ 1.26.0**

### Таблица конфигурации DDUI

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `ddui.enabled` | `true` | Главный выключатель |
| `ddui.replace-delay-ticks` | `20` | Задержка перед show при смене экрана |
| `ddui.session-timeout-ticks` | `6000` | Таймаут серверной сессии (0 = выкл) |
| `ddui.max-inbound-updates-per-tick` | `32` | Лимит `ServerboundDataStore` |
| `ddui.max-outbound-updates-per-tick` | `64` | Лимит исходящих DataStore update |
| `ddui.default-theme` | — | Тема по умолчанию |
| `ddui.themes.<alias>.*` | — | `style-id`, `resource-pack` |

### Протокольные tier

| Tier | Min protocol | Клиент получает |
|---|---|---|
| `unsupported` | < 1.26.0 | JSON forms / ModalForm |
| `base` | 1.26.0 | Open + DataStore push |
| `with_screen_close` | 1.26.10 | + `CloseScreen` |
| `full` | 1.26.20 | + `dataInstanceId` на форму |

```php
$player->supportsDduiDataInstanceId();
$player->supportsDduiScreenClosed();
```

### События

- `DduiFormCloseEvent`, `DduiFormClientUpdateEvent`, `DduiFormResponseEvent` — все cancellable до обработчика формы.

Документ: `docs/plugin-api-ddui.md`, smoke: `docs/DDUI_MANUAL_SMOKE.md`.
 (целевой smoke — **1.26.60**). Отключить: `ddui.enabled: false`.

### Детект и API игрока

```php
if($player->supportsDdui()){
    $player->sendDduiForm($form);
    $player->pushDduiClientUpdates($updates); // список DataStoreUpdate
}
$player->getDduiProtocolTier(); // full | with_screen_close | base | unsupported
$player->resolveDduiStyleId('rubyx:postsystem'); // → minechat:postsystem
```

Подробно: `docs/plugin-api-ddui.md`, контракт пакетов: `docs/DDUI_WIRE_CONTRACT.md`.

### Встроенные экраны (vanilla `screenId`)

| screenId | Назначение |
|----------|------------|
| `minecraft:message_box` | Два действия; fallback на `ModalForm`, если DDUI нет |
| `minecraft:custom_form` | Колонка контролов (label, toggle, textfield, button, …) |

Реализация: `src/form/ddui/` — `DduiSessionManager`, `DduiNetworkAdapter`, `DduiLayoutBuilder`, `DduiClientUpdates`.

### Reactive push

Порядок открытия: **DataStoreChange** (полное дерево) → **ShowScreen** (`screenId`, `formId`, опционально `dataInstanceId` на ≥ 1.26.20).

Дальше сервер пушит пути вроде `layout.2.text`, `title`, `button1.onClick` без `sendForm()`.

Опциональный hook: `DduiFormOnOpen::onDduiOpen()`.

События: `DduiFormCloseEvent`, `DduiFormClientUpdateEvent`, `DduiFormResponseEvent`.

### Theme API (RP styling)

Скан **resource stack** на `ddui/styling/*.json` (`minecraft:ui-style`, format `beta`).

- Реестр: `DduiThemeRegistry` (boot + `/resourcepacks reload`).
- В форме: `DduiLayoutBuilder::applyThemePreset('rubyx:postsystem')` или root `styleId`.
- Ограничение клиента: стиль в основном **панель / label / textfield**; не дублирует JSON UI PostSystem layout.

Док: `docs/DDUI_THEMING.md`. Пример пака: `resource_packs/MineChat_PostSystem/ddui/styling/minechat_postsystem.json`.

- **`/ddui`** (`pocketmine.command.ddui`) — JSON-хаб с переходом на тестовые DDUI-экраны (MessageBox, CustomForm, reactive demo, PostSystem demo, **minechat:postsystem_chat spike**).

`FormManager::sendDduiForm($player, $form, $forceOpen)` — те же правила single-open/cooldown, что у `sendForm()`.

### Кастомный screenId (эксперимент)

### Смешивание с JSON-формами

`Player::sendForm()` закрывает активные DDUI-сессии. `sendDduiForm()` закрывает legacy ModalForm. Одновременно держать JSON PostSystem и DDUI push **нельзя** без отдельного кастомного экрана.

## `/status` — понятный статус сервера

**Зачем.** Старый `/status` был техническим (TPS, кБ/с, «чанки»). Для операторов в консоли удобнее читать простыми словами: плавность игры, кто онлайн, чем подключаются, сколько плагинов живы.

**Что показывает** (rus; eng зеркалит те же ключи):

| Строка | Смысл |
|--------|--------|
| Ядро | Имя + версия ядра (`RubyxGames`) |
| Игроков онлайн | `сейчас / лимит` |
| Работает уже | Аптайм |
| Плавность сейчас / за время (TPS) | Тики в секунду и нагрузка тика |
| CPU | Загрузка хоста 0–100% (`/proc/stat`) |
| RAM | занято / всего (MB или GB) и % |
| Диск | занято / всего на ФС data-dir (MB или GB) и % |
| Трафик к / от игроков | Исходящий / входящий кБ/с |
| Тип подключения | Активные транспорты (`nethernet`, `raknet`, …) |
| Плагинов включено | `enabled / всего` |
| Фоновых потоков | Число потоков процесса |
| Мир … | Куски карты в памяти, обновляемые, объекты, мс на тик |

Если тик заморожен (`/tick freeze`) — отдельная красная строка: игровое время и мобы на паузе.

**Как пользоваться.** Консоль или игрок с `pocketmine.command.status`: `/status`. Строки из `resources/translations/{rus,eng}.ini` (`pocketmine.command.status.*`); после правок ini — codegen `build/codegen/known-translation-apis.php`.

**Код.** `src/command/defaults/StatusCommand.php`.
